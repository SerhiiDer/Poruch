# Як почати працювати над «Поруч»

Інструкція для учасників, які не програмують. Код ви писатимете разом з Claude — просто описуєте словами, що хочете змінити.

Не бійтеся щось зламати: кожна ваша зміна живе в окремій «гілці» (копії проєкту), і Serg переглядає її, перш ніж вона потрапить в основний застосунок.

---

## 1. Акаунти

1. **GitHub** — зареєструйтесь на [github.com](https://github.com) і надішліть Serg свій логін.
2. Serg надішле запрошення — **прийміть його** в листі від GitHub або на [github.com/notifications](https://github.com/notifications).
3. **Claude** — потрібна підписка Pro або вище на [claude.ai](https://claude.ai).

## 2. Програми на компʼютері

Встановіть по черзі (усе безкоштовне, кнопка «Next» скрізь підходить):

1. **Git** — [git-scm.com/downloads](https://git-scm.com/downloads)
2. **Node.js** (версія LTS) — [nodejs.org](https://nodejs.org)
3. **VS Code** — [code.visualstudio.com](https://code.visualstudio.com)
4. У VS Code: зліва іконка квадратиків (Extensions) → знайдіть **Claude Code** → Install → увійдіть своїм акаунтом Claude.

На телефон — застосунок **Expo Go** (App Store або Google Play).

## 3. Завантажити проєкт (один раз)

У VS Code: меню **Terminal → New Terminal**, і по черзі:

```
git clone https://github.com/SerhiiDer/Poruch.git
cd Poruch/apps/mobile
npm install
cp .env.example .env
```

Потім **File → Open Folder** → відкрийте папку `Poruch`.

> Якщо `git clone` пише `SSL certificate problem` — виконайте
> `git config --global http.sslBackend schannel` і спробуйте ще раз.

## 4. Запустити застосунок на телефоні

```
cd apps/mobile
npx expo start
```

- **iPhone:** наведіть звичайну камеру на QR-код у терміналі.
- **Android:** відкрийте Expo Go → «Scan QR code».

Телефон і компʼютер мають бути в **одній Wi-Fi мережі**. Не підключається — зупиніть (`Ctrl+C`) і запустіть `npx expo start --tunnel`.

Поки сервер працює, кожна зміна в коді одразу видно на телефоні.

## 5. Як працювати з Claude

1. Відкрийте панель Claude Code у VS Code.
2. Опишіть задачу звичайними словами, наприклад:
   *«Хочу на сторінці івенту кнопку "Додати в календар"»*.
   Claude сам створить окрему гілку й напише код.
3. Подивіться результат на телефоні. Не подобається — скажіть, що змінити.
4. Коли все добре, напишіть: **«Відправ це Serg на перевірку»**.
   Claude збереже зміни й створить Pull Request — запит для Serg.
5. Serg перегляне й додасть у застосунок.

Перед новою задачею скажіть Claude: **«Почнімо нову задачу»** — він оновить проєкт і створить нову гілку.

## 6. Чого не робити

- Не просіть Claude змінювати **базу даних** (таблиці, заклади, івенти) — це робить Serg. Якщо для ідеї потрібні нові дані, просто опишіть це, Claude запише для Serg.
- Не вставляйте в код і в чат паролі чи «секретні» ключі.
- Не встановлюйте нові програми чи бібліотеки самі — Claude знає, які можна.

## 7. Якщо щось пішло не так

- **Застосунок показує червону помилку** — сфотографуйте/скопіюйте її й покажіть Claude: «ось помилка, виправ».
- **Хочу повернути, як було** — скажіть Claude: «відкоти мої зміни в цій гілці».
- **Нічого не зрозуміло** — пишіть Serg. Зламати основний застосунок ви не можете: усе проходить через його перевірку.
